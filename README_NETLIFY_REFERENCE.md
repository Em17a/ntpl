# Nightplay

Nightplay 是一个双人互动房间原型，包含静态前端、Netlify Server WebSocket 房间服务和 Netlify Database 持久化。

## 本次语音更新

已增加双人 WebRTC 实时语音。请同时部署本项目的 `public/index.html` 和 `netlify/server/index.ts`；仅上传静态页面不会启用 WebRTC 信令。具体 TURN 环境变量、部署要求和验收步骤见 [`VOICE_SETUP.md`](./VOICE_SETUP.md)。

## Netlify 部署提醒

- 保留项目现有的 Netlify Database 和 WebSocket 服务配置。
- 将本 ZIP 中的完整项目源码同步到原 Netlify 项目仓库，再触发一次部署。
- 网站需通过 HTTPS 访问，浏览器才能提供麦克风授权功能。
- 建议配置支持 REST shared-secret 认证的 TURN 服务；无 TURN 时，部分网络环境可能无法建立点对点音频连接。

## 语音隐私

麦克风不会自动开启，必须由参与者主动点击并授权。静音或结束通话可随时操作。本版本不录音、不保存音频；语音信令不写入聊天历史。

## 偏好匹配更新

- 大厅新增“偏好匹配”：填写昵称，选择自己的性别（男性 / 女性 / 其他或不便透露）以及希望匹配的对象（男性 / 女性 / 不限）。
- 仅当双方选择互相符合时才会配对；成功后自动创建私人双人房间，并沿用原有聊天与双向语音功能。
- 匹配等待支持取消；断线后等待队列会在约 45 秒无心跳后自动清理，旧匹配记录会在 1 天后清理。
- 点击房间内“结束本轮”会结束本轮互动，并让双方自动退出房间。
- 本次新增数据库迁移位于 `netlify/database/migrations/20261120050000_add_matchmaking_queue/migration.sql`。Netlify 会在部署生命周期中自动应用该目录中的迁移；无需手动登录数据库执行 SQL。

## 部署

将 ZIP 内项目文件完整同步到现有 GitHub 仓库并触发 Netlify 部署即可。部署前提是原 Netlify 项目已启用 Netlify Database（本项目原版本已使用该数据库）。Netlify 会先应用新增迁移，迁移成功后再发布新版本；如果迁移失败，部署不会发布。


## 当前主页功能

主页仅保留双人私人房间、实时文字聊天/可选双向语音，以及新增的节拍器寸止挑战。挑战支持双方实时同步节奏速度（40–220 BPM）、节拍力度（1–5）、开始、暂停和结束。力度只控制浏览器节拍提示音量和视觉脉冲，不控制外接设备。


## 控制方 / 受控方角色与匹配

- 创建或加入私人房间时可选择“控制方 / 受控方 / 由系统自动分配”。同一房间的两位成员必须分别担任不同角色；如选择冲突，服务端会提示更换角色。
- 偏好匹配新增“希望自己担任的角色”（控制方 / 受控方 / 不限），性别与角色偏好均需兼容才会配对。双方都选不限时，系统将第一位分配为控制方、第二位分配为受控方。
- 角色保存在数据库成员记录中；服务端对节拍控制权限进行校验。只有控制方能调整 BPM、力度、开始、普通暂停和结束挑战。
- 受控方不能修改控制参数，但可使用独立的紧急停止按钮；任一方离开或 WebSocket 断线时，正在运行的挑战自动停止。
- 新增迁移：`netlify/database/migrations/20261120061000_add_challenge_roles/migration.sql`。

## 联系方式防泄漏（2026-11-20）

- 文字消息在浏览器和 WebSocket 服务端双重检测；服务端检测为最终拦截点，命中的原文不会进入消息数据库或广播。
- 检测覆盖手机号、邮箱、常见社交平台账号/链接、中文数字及常见空格/标点拆分，并对同一用户 12 秒内相邻消息做短时拼接检测。短时拼接文本仅保存在当前 WebSocket 会话内存中，不写入数据库。
- 首次命中警告；再次命中暂时限制消息/语音；持续违规升级限制。违规计数目前保存在当前 WebSocket 会话内存中，重新连接或实例切换后不保证延续。
- 语音检测使用浏览器 SpeechRecognition 的 `processLocally` 设备端模式（中文 `zh-CN`）。只有浏览器明确支持该能力时才允许开启麦克风；不回退到云端识别。若支持语言包安装，会由浏览器安装设备端语言模型。
- 识别到疑似联系方式后，客户端立即禁用本地音轨并停止识别，再向服务端发送违规事件。识别文本只存在于当前事件处理内存中，不展示、不写入日志、不保存为聊天记录。
- 重要限制：浏览器端语音识别属于尽力而为的客户端保护，识别有延迟、误识别和漏识别可能；WebRTC 音频在识别结果返回前可能已经传出，且有技术能力的用户可修改客户端绕过。该方案不能保证零泄漏，也不能替代服务端媒体中继/审核。若浏览器不支持 `processLocally`，本版本会阻止麦克风开启。
- 用户界面会告知语音识别用途。上线前仍需完成适用法律要求的隐私告知、同意与数据处理评估。
- 为降低识别延迟造成的语音先行泄漏，WebRTC 上行音频增加约 1.6 秒本地缓冲；命中后通过音频增益门立即静音并清空后续输出。缓冲会增加通话延迟，识别速度仍可能慢于缓冲时间，因此不能承诺完全零泄漏。
